# AppSentinel 轻量监控设计

简体中文 | [English](2026-09-19-lightweight-monitor-design.md)

## 目标

AppSentinel 启动并监控 Mac 所有者选择的任意 macOS 应用。轻量版在等待 Apple 批准 Endpoint Security 权限期间提供实际保护，只使用 macOS 内置能力，不要求关闭系统完整性保护（SIP）。

第一个真实使用场景是网络代理应用，但任何规则和组件都不会绑定特定厂商或 Bundle ID。

## 使用流程

1. 用户运行 `appsentinel run /Applications/Example.app`。
2. AppSentinel 记录目标身份，并建立受保护系统状态的基线。
3. AppSentinel 启动目标应用，监控其完整子进程树。
4. 目标及其所有子进程退出后，监控器随之退出。
5. 发生严重策略违规时，AppSentinel 保存证据、结束整个受监控进程树，并在可安全恢复时还原启动前的代理设置。

首个界面采用命令行。后续原生图形启动器将复用同一个监控核心，不改变策略行为。

## 监控模型

监控器组合三类数据源：

- 在受支持的 macOS 上使用 `eslogger` 近实时获取进程和文件系统事件，仅在监控会话期间运行。
- 定期检查进程树和网络状态，作为降级方案及独立校验。
- 比较证书、启动项、系统扩展、代理设置和用户敏感路径的前后快照。

如果 `eslogger` 不可用或权限不足，AppSentinel 会继续以降级模式运行，并在终端和会话日志中明确提示。

## 策略

策略只针对用户选定的应用及其子进程。AppSentinel 不会把无关系统活动写入证据日志。

以下严重事件会触发终止受监控进程树：

- 新建或修改 LaunchAgent、LaunchDaemon、登录项或系统扩展；
- 读取或修改 SSH 私钥、浏览器凭据数据库、密码存储或无关钥匙串数据；
- 执行未获允许的 shell、AppleScript 或刚释放到磁盘的可执行文件；
- 在会话策略允许范围之外修改系统代理、DNS 或路由；
- 在证书登记窗口之外新增、删除、替换证书或修改其信任设置。

证书登记必须显式开启。一个会话可以设置五分钟登记窗口，期间最多记录一张新增证书。AppSentinel 不会自行信任该证书，信任授权仍由 macOS 控制。任何额外证书变化都视为严重事件。

初始策略有意保持保守。预期的可执行文件、脚本、网络变化和证书登记必须在启动前通过命令行参数或策略文件明确允许。

## 响应和恢复

发生严重事件时，AppSentinel：

1. 先冻结或结束子进程，再结束根进程；
2. 把触发事件、进程祖先链、可执行文件哈希和相关状态差异写入本机会话目录；
3. 在不影响无关网络接口的前提下恢复启动时的系统代理配置；
4. 明确报告无法安全撤销的操作。

轻量版不会自动删除证书、启动项或用户文件。它会保留证据，并给出准确的修复命令供用户审核。

## 隐私和存储

日志保存在 `~/Library/Logs/AppSentinel/`。日志仅包含归属于受监控进程树的事件，以及明确受保护位置的状态变化。文件内容、凭据和浏览器数据不会复制进日志，也不会有数据离开本机。

## 实现结构

- `AppSentinelCore`：进程身份、祖先链跟踪、策略判断、基线、证据记录和响应决策。
- `AppSentinelSystem`：`eslogger`、进程检查、证书、受保护路径、网络状态和进程终止适配器。
- `appsentinel`：选择目标、声明预期行为、启动、监控和展示结果的命令行工具。

策略判断使用纯 Swift，并通过合成事件测试。系统适配器提供范围窄的协议，使测试无需修改真实 Mac 状态也能验证响应逻辑。

## 验证

自动化测试覆盖进程树归属、证书登记数量限制、敏感路径规则、允许的 shell 执行、网络状态策略、降级模式和严重事件响应顺序。

集成检查使用无害的测试进程和临时目录，验证启动与退出联动、子进程跟踪、本地证据生成，以及主动违规测试进程被终止。测试不会修改真实证书、系统代理或正式启动项目录。

## 限制

没有 Endpoint Security 权限时，轻量监控只能在事件上报后观察并响应，无法保证每项操作都在完成前被阻止。轮询降级模式的检测窗口更长。程序会始终明确展示这些限制；只有经过授权的 Endpoint Security 系统扩展替换观察层后，这些限制才会消失。
